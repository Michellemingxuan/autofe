stage 0.5

Discover

src/discovery/ · stage.py loop.py prompt.py sandbox.py guards.py screen.py runs LLM-written code - skipped in A ran in B · loop ≈ 22 s

In

  • The Dataset's base columns. Test rows never reach discovery; ids are checked.
  • screen_train.csv (fit) and screen_valid.csv (score), or the whole splits with screen_data: splits
  • few_shot.csv, column_descriptions.json, task_description
  • history.csv: every earlier run's proposals with their verdicts
  • A strategy (caafe · elfgym · ferg · featllm · promptfe) and a model

Does

Asks for 5 features per round, runs each block, checks its values and scores it against a fixed baseline. Every outcome goes back into the next round's prompt.

min_delta is unset, so every block that ran is forwarded. The screen only removes code that breaks or duplicates a column; the verdict judges the rest.

Forwarded code is rerun on all three splits and checked again. A feature that fails there is dropped and recorded as rejected.

Every run writes to outputs/<run.name>/<timestamp>/

pipeline_status.json
rewritten on every stage transition: {schema_version, run, status, started_at, finished_at, stages: [{key, label, status, elapsed_seconds, detail, checks: [{name, passed, detail, severity}], error}]}
run.log
every log line, including the stage board after each transition
config.resolved.yaml
the config as run, with defaults filled in
summary.json
every stage's summary, plus library versions
report.md
the readable report: data, quality, verdict, comparison, ranking

A stage ends with ! when one of its checks fails and X when it raises; after an X every later stage is marked - with “not reached”. The run is succeeded, succeeded_with_warnings or failed.
